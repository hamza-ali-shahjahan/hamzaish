# 2026-08-20 — Learnings

Two lessons from one session, and they turned out to be the same lesson wearing
different clothes: **a system that only measures correctness will not notice the thing
that is actually costing you.** One was costing money. The other was risking three
weeks of work.

## Cross-product learning 1: metered spend belongs to a customer, not to a code path

**Setting**: Patently (`products/copyright`) was billed **$93.91 for Aug 1–17 with zero
active users**. Not a traffic spike, not abuse — two scheduled jobs, running on a timer,
for nobody.

**The trap**: the factory already had `abuse-and-cost-controls.md`, and Patently followed
it. A per-query byte ceiling was set. A local-first cache was built. Per-user rate limits
were enforced. Per-run cost tracking existed and was surfaced in `/admin`. Every one of
those guards missed:

| Guard | Why it missed |
|---|---|
| `maximumBytesBilled` = 300 GB | Set from an **unmeasured guess**. Real cost per call: 231 GiB. The ceiling sat above the problem, so it never fired. |
| Local-first cache | The cache key embedded **today's date** under a 7-day TTL. The key rotated faster than the TTL — a guaranteed miss, every day, by construction. |
| Per-user rate limits | Rate limits are per user. **A cron has no user.** |
| Per-run cost tracking | Tracked cost **inside user sessions only**. Machine spend had nowhere to land, so the dashboard read $21 lifetime against a real $94/month. |

**The pattern**: every guard bounded *how big a single call could be*. None bounded
*whether the call should happen at all*. A robot on a timer spends right up to every
ceiling you set, forever, on behalf of nobody.

**Rule for the factory**: attach the right to spend to a **person** — an entitlement
carried at runtime and checked at the leaf where money actually leaves. A scheduled job
can name itself but has no payer, so it is refused before the provider is contacted. This
converts *"remember to switch the cron off"* (discipline, which decays) into *"the cron
cannot switch spending on"* (structure, which holds).

**Sub-lessons worth carrying separately:**

- **Never trust a cost comment you did not measure.** Patently's source comments asserted
  partition pruning, ~1 MB lookups, and free-tier coverage. All three false; none ever
  tested. A BigQuery dry run is free and exact. Measure, then write the number **and the
  date** into the comment — a cost claim without a date is a rumour.
- **A filter only prunes if you own the table.** `WHERE publication_date BETWEEN …` looked
  like partition pruning and pruned nothing, because the public table isn't partitioned
  on it. Every query shape — one day, two years, or a single row by primary key — cost an
  identical $1.41.
- **Fail closed on money; fail open on access.** Usage limits should fail open so a flaky
  DB can't lock users out. Spend guards must fail closed so a flaky DB can't become an
  open cheque. Patently shipped this backwards on the first pass (a failed ledger read
  reported "$0 spent" and let the query through) and a security review caught it.
- **Count outputs, not executions.** "Ran 77 times" reads healthy on a dashboard. The truth
  was 77 runs, **0 items found, 0 emails sent**, for one watchlist owned by a free test
  account. Work that produces nothing isn't neutral; it's pure cost.
- **The operator escape hatch must be un-acquirable by a server.** Deliberate spending
  (re-seed a corpus) must not be an env var — an env var on the server hands every cron
  the right back. Make it an in-process call only a human-run script can obtain.
- **Free tiers are a trap for reasoning.** "1 TB/month free" is *four calls* at 231 GiB.
  Convert every free tier into number-of-operations before believing it.
- **A trial credit hides your steady state.** The first half of the month billed $0
  because credit absorbed it; the first real invoice looked like a spike but was the
  normal rate arriving late. Treat any "$0 so far" as unmeasured, not free.

**Lives as**: [`factory/playbooks/mvp-stage/spend-belongs-to-a-customer.md`](../../factory/playbooks/mvp-stage/spend-belongs-to-a-customer.md).
Filed under **mvp-stage, not scale-stage**, deliberately — the old playbook's home encodes
"more users → bigger bill", and that model is exactly what let this happen. The bill
arrived at zero users.

## Cross-product learning 2: work that exists only on one machine

**Setting**: opening the factory repo to publish learning 1 revealed **~3 weeks and 6,080
lines across 90 files** sitting uncommitted — the entire v2.25.0 release, its changelog
entry written and its version bumped, none of it in git. No stash, no branch, no backup.

**The trap**: committing feels like *publishing*, so it waits for the work to be "ready."
But a local commit publishes nothing. The instinct is right about pushing and completely
wrong about committing, and conflating the two is the whole bug. Agent sessions make it
worse — each is scoped to a task, ends cleanly, and nobody owns the question *"does this
still exist tomorrow?"*

**What rode along with it:**

- **Silent divergence.** While the work sat, `origin` gained two commits — including
  changes to a file the uncommitted work had rewritten. The conflict was invisible until
  a push was attempted, by which point it was harder than it would have been on day one.
- **Three weeks of deferred gate failures, discovered at once**: absolute machine paths
  bound for a permanently public repo, six decision records missing required fields, a
  stale count badge. Trivial individually; an afternoon together.

**Rule for the factory**: **finishing a thing means committing it — not pushing it,
committing it.** And when you find a backlog, **protect it before you improve it**: the
tidying is exactly when a bad `checkout` happens, so snapshot to a throwaway branch first
and make every later step reversible.

**Lives as**: `bun run check-work-at-risk` (uncommitted paths + age of the oldest,
unpushed commits, divergence, missing upstream — warn-only by default, `--strict` for
hooks), surfaced once per session by the SessionStart hook, AGENTS.md rule #17, and
[`brain/anti-patterns/work-that-exists-only-on-one-machine.md`](../anti-patterns/work-that-exists-only-on-one-machine.md).

## What the two share

Both are failures of **what gets measured**. The factory measured whether code was
correct, and could not see that correct code was billing for nobody. It measured whether
work was good, and could not see that good work existed in only one place. Correctness
gates are necessary and they are not sufficient — a system also needs to watch the money
and the durability, because neither shows up as a failing test.

**The generalisation worth keeping**: when adding a guard, ask what it *cannot* see.
Every guard in the cost playbook could see the size of a call and none could see its
authority. That blind spot, not any individual rule, was the bug.

## Shipping the guard hooks into the repo

**What surprised me — I scoped real work against superseded files.** Two guards
existed twice on disk: `~/.claude/hooks/guard-repo-visibility.sh` (personal,
hardcoded) and `~/.claude/hooks/guardhooks/guard-repo-visibility.sh` (generalized,
config-driven). I read the shallower path, found personal identity baked in, and
concluded two of four guards needed generalizing. Both were already portable. The
tell arrived only when a guard *blocked* me and its error message didn't match the
source I'd read.

The mechanical fix, and the rule worth keeping: **to find which hook actually
fires, read the registration, not the filesystem.** `settings.json` →
`PreToolUse` names the exact path. A file that merely exists at a plausible path
is not evidence it runs. Same shape as the provenance anti-pattern — "it resolves"
never meant "this is the thing that resolved."

**What worked — proving the tests could fail.** 58 tests passing on the first run
is weak evidence; the suite could have been asserting nothing. Neutering one guard
to `exit 0` and confirming that exactly its 9 blocking cases failed (and no others)
turned "the tests pass" into "the tests discriminate." Cheap, fast, and it belongs
in any suite whose subject is a *refusal* — where the happy path is silence and a
broken guard looks identical to a working one.

**The build produced its own best test case.** Writing the visibility guard's
source tripped the visibility guard: a heredoc containing a guarded command string
is indistinguishable, to a regex over the tool call, from running it. Fail-safe and
correct, but a real false-positive class — recorded in the folder's *Known limits*
rather than worked around silently. Guards that match on command text will always
have this edge; the honest move is to name it where a user will hit it.

**Restraint that held:** the operator's live `~/.claude/` config was not touched,
and the redundant double-registration found there was recorded, not fixed. Changing
someone's personal safety configuration mid-build — even to tidy it — is exactly
the class of unrequested action the guards exist to prevent.

## Grade a repo's claims against its CHANGELOG, not its README

Scouted `langchain-ai/deepagents` (28k stars, MIT, healthy on every axis). Its most-repeated
headline feature — planning-first TODO lists — **was removed from the default stack**, recorded
plainly in `libs/deepagents/CHANGELOG.md:59` and nowhere in the marketing. Every secondhand post
still lists it. A second headline (`/memories/` long-term memory) never existed in library code at
all; the real implementation is the agents.md spec, and `/memories/` is only a docstring example
of a route the user wires themselves.

**The check:** when `/repo-scout` grades a claim, the changelog and the committed prompt/tool
snapshots outrank the README, the docs site, and the announcement. Deleted features leave a trace
in exactly one place. Added to the deep-dive brief's mental checklist; candidate for an explicit
brief line if it recurs.

## Escaping the boring channel and leaving the interesting one open

Same repo, `middleware/skills.py`: skill *load warnings* are `html.escape(json.dumps(...))`-wrapped
and labelled untrusted before entering the system prompt (`:882-891`) — while skill **descriptions**
are interpolated raw (`:869-877`). Someone thought carefully about untrusted text, then applied it to
the low-value channel. Any SKILL.md in a scanned directory injects straight into the system prompt.

**Why it matters here:** we now install skills from a plugin marketplace, so third-party-authored
frontmatter reaches our context too. The rule worth pinning: *the channel you thought about is rarely
the exposed one — enumerate every path third-party text takes into a prompt, not the obvious one.*
Check-ladder candidate: a `/security-check` line that flags unescaped third-party-authored text
rendered into any prompt surface. Not built — recorded so it can become a check rather than prose.

## Portability thesis got its second, stronger data point

`docs/host-portability.md` rested on one alternative host (`deepseek-harness`, TypeScript, developer
preview). deepagents is a second, in Python, citing agentskills.io/specification directly
(`middleware/skills.py:138`) — and `deepagents-code` reads `~/.claude/skills/` and `.claude/skills/`
at highest precedence. Two independent hosts converging on the same markdown format is a standard
forming, not a coincidence. Our 44 skills use only `name` + `description`, the maximally portable
form; unknown keys are silently dropped, not errors. Still **mapped, not tested** — the gate is one
named skill firing end-to-end under a `FilesystemBackend`-configured agent.

## Recall that lagged its own files — and the same bug one level up

**What happened.** An external repo (Graft) came in as "look at what this does." The brain already
held a code-grounded study of it from three weeks earlier, with an approved trial and recorded
watch triggers — so the useful question was never "what could we take," it was "which of our own
triggers fired." Searching before answering was the cheapest good decision of the session.

**What worked.** Grading the claim rather than repeating it. The pitch said the generated repo map
is shared with a team via git; the tool's own README says it is gitignored as a regenerable cache
and every teammate rebuilds their own. The gap between what a thing is sold as and what it does was
worth more to report than the feature itself. Same shape as the `--deep` conflation: the headline
capability ("markdown docs, no keys needed") is actually two layers, and only one of them is keyless.

**What surprised me — the highest-signal thing here.** The code defect and the communication defect
were *identical*. `ask.ts` knew when files had changed and mentioned reindexing only in its
*no-hits* footer — i.e. in the one case where being stale was harmless. A proposal knew its
recommendation and put it under the analysis, where the reader had already stopped. In both, the
information existed, was correct, and sat where it could not act. **"Where does the reader actually
look?" is a debugging question, not a writing one.** Worth carrying into anything that reports:
placement is part of correctness, not presentation.

**What it cost.** The standing "always lead with a recommendation" rule was followed *structurally*
— a heading existed — and still failed. Structure that survives only when unpressured isn't
structure. It is now a required receipt line with a gate that rejects both omission and hedging,
and `NA` is the honest out. Prose → shape → check, the ladder working as intended.

**Two smaller ones.** A latent trap is cheapest to fix before anything depends on it
(`documents.mtime` held wrapped int32 garbage; nothing read it yet, which is exactly why it was
free). And a limit asserted as a passing test beats a limit described in a comment — the freshness
probe's blind spot is now a fact, not a claim.
