# 2026-09-04

- **Verify a deliverable at its destination path, by content, after every write —
  not just the intermediate you produced.** Mid-goal-loop, a concurrent session's
  PR #97 merge-and-sync reverted the modified-but-uncommitted hero GIF back to
  HEAD; untracked files survived, the tracked binary didn't. The fresh-eyes
  reviewer caught it only because it md5'd and re-exploded the file *at the
  destination* instead of trusting the pre-extracted frames. Operating
  principle 14's shared-working-tree collision, observed live — an uncommitted
  tracked file is a hostage to any other session that syncs the tree.
- **Two recording tapes outputting to the same asset path is a landmine.**
  scripts/hero.tape (old animation) and scripts/hero-flow.tape (new) both write
  docs/assets/hamzaish-hero-card.gif; re-running the old one silently clobbers
  the new. Fixed by removing the stale tape in the same PR that shipped the
  new GIF (`bun run hero` and scripts/hero.ts stay).
- **A self-paced replay script + a dumb vhs tape beats scripting the pacing in
  the tape.** Putting all timing in hero-flow.ts (with a HERO_SPEED=0 instant
  preview mode) made the recording reviewable as plain text before spending a
  45s render, and the tape stays 3 lines.
