# Learnings — 2026-08-14

## A gate that never reads its evidence isn't a gate

`check-validation` printed an evidence count next to its verdict for two months
without the count ever being able to change the verdict. It was a *label*, not a
*condition* — and once evidence is decorative, nothing stops it from being wrong,
which it also was (counted file-wide, so the debt block scored as evidence for
validation). Both defects leaned toward a pass, because nothing was pulling the
other way. The test to apply to every other `check-*` guard: **can its happy path
be reached from an empty file?** If yes, it's documentation with an exit code.

## The local workaround is what let the shared defect survive

muakkil's ledger dodged the miscounting by writing its debt heading backwards
(`### Building before validation — 2026-07-02`) plus a comment explaining why.
That fixed one product's markdown and removed the only pressure to fix the script
every product shares — the defect became invisible again the moment it was routed
around. A workaround in *one* consumer of shared tooling should be treated as an
open ticket against the tooling, not a resolution: the comment explaining the dodge
is the bug report, and it belongs in the tool, not the file.

## Recording a skip honestly should never improve your numbers

The sharpest form of the counting bug: filling in the "I built before validating"
block *raised* the evidence count. The escape hatch and the thing it's an escape
from were parsed by one regex, so honesty and validation became indistinguishable
to the machine. Anywhere the factory offers a "record it instead of doing it" door
(validation debt, retro skips, ambiguity declarations), the record has to be
counted as a *different kind* of thing from the work — or the door quietly becomes
a shortcut through the wall.
