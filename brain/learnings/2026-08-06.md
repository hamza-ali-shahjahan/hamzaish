# Learnings — 2026-08-06

## repo-scout field run #1 (Horizon) hardened the skill itself
The first single-URL run (google/adk-samples · core/python/long-horizon-harness)
surfaced four skill gaps: sub-path (monorepo) health must be verified at BOTH
levels (the parent's 10k stars masked a 2-days-public, single-author, v0.1.0
sample); sparse+shallow clones for big repos (6.8MB pulled instead of 292MB); a
`Cost:` line on every run, not just trending (this deep-dive: ~210k subagent
tokens, ~10 min); and two brief hardenings (grade the requester's paraphrase as
the CLAIM — the surfaced misconception was the most valuable finding; quoted
instruction-shaped tags must arrive inert — one literally arrived live and the
harness had to neutralize it). Shipped to the standalone repo same day (PR #1,
contract CI green); the factory copy awaits operator review to keep the
five-gates sync rule honest.
**Meta-lesson: a skill's first real field run IS its best test suite — run the
enrichment pass immediately after, while the friction is fresh.**

## Enablement gap: the factory announces itself everywhere EXCEPT home
v2.24.0's plan/receipt protocol fires via the product tendril marker — so it
covers product repos only. A session inside the Hamzaish repo itself produced
no bookends, and the operator had to ask (again) whether Hamzaish was being
used at all — the exact invisibility v2.24.0 set out to kill, one level up.
The hook existed and was registered; its SCOPE was wrong. Compounding lapse:
the session skipped the fresh-session changelog read that would have surfaced
the 2-day-old protocol. Fix proposed: `factory-session-context.sh` also fires
in the factory repo (canonical-path match), factory-flavored catalog.
**Rule of thumb: when shipping a visibility mechanism, enumerate every surface
the operator actually sits in — the builder's own repo counts most.**
