# 2026-09-19

- **A check that only ever runs on the maintainer's machine cannot see what a
  stranger hits.** Every guard was green while every install outside
  `~/Claude/Hamzaish` had its global commands and freshness hook aimed at a folder
  that didn't exist: setup never set `HAMZAISH_ROOT`, and the
  `${HAMZAISH_ROOT:-$HOME/Claude/Hamzaish}` fallback is one person's folder layout.
  Found by installing into a throwaway folder with a throwaway `HOME`; now pinned in
  CI as `scripts/stranger-install.test.ts`, with `bun run doctor` for humans.
- **Untracking user data breaks tests that leaned on it — find out on a fresh
  clone, not after the push.** Two tests (the corpus walk, the session stamp) passed
  only because the maintainer's product folders were on disk. After `products/` went
  user-local they would have failed in CI and nowhere else. Running every CI step on
  a fresh clone of the branch caught it before publishing; each test now plants a
  throwaway product and removes it.
- **After a commit untracks files, never sync local by switching to the old main.**
  The old commit still tracks them, so `git switch main` overwrites the
  now-ignored working-tree copies with main's older versions, and the pull that
  follows deletes them — the /pr flow's step 9 (and `gh pr merge --delete-branch`,
  which switches for you) would have done exactly that to every product's notes.
  Safe order: fetch, confirm the branch's tree equals the new `origin/main`, move
  `main` with `git branch -f main origin/main` from the branch, then switch. The
  working tree never passes through the old commit. Encoded in `/pr` step 9.
