# 2026-10-07

- **Legal exposure is a scaffolder default, so it has to be a factory default.**
  A sweep of 78 repos found 37 carrying at least one per-unit legal trap (age gate,
  Google-hosted fonts, replay, marketing email, renewal terms, DMCA) — none chosen,
  all inherited from whatever generated the first commit. The fix that scales is the
  one that lands in the starter and the `/ship` gate (`scripts/check-legal-traps.ts`),
  not one more checklist.
- **A regex scanner earns trust only through a refutation pass.** The first version
  "passed" age gates on a terms page's "18+", on `rating * 18 +`, and on "13 million
  websites"; it called `hmac.digest()` a newsletter and a CSV import a hosting
  service. Running it across real repos, then having a reader confirm or refute every
  FAIL, turned each false call into a test case. Same shape as the agent-blind judge:
  the scanner proposes, a reader disposes, and an accepted false positive is written
  down (`legal-traps.json`) with its reason.
- **Front-end gates don't cover OAuth account creation.** Supabase (and Clerk) create
  the user on the provider round-trip, before any page-level age check can run on a
  login-page Google button. Gate the button on every page that has one, and treat a
  server-side "before user created" hook as the real fix.
