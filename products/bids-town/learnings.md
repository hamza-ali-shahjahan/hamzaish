# Learnings — bids.town

_Capture the transferable lesson only — never keys, credentials, or proprietary internals._

## What worked

- **Forking a proven engine beats rebuilding one.** bids.town reuses productbids' auction
  mechanics wholesale — the ceiling maths, the idempotent payment path, the SSRF-hardened
  scraper, the anti-abuse layer, the token design system. Only the presentation and the
  economy on top are new.
- **Validating SQL against a throwaway Postgres container before shipping it.** `docker run
  postgres:17-alpine`, create the three Supabase roles (`anon`, `authenticated`,
  `service_role`), replay the migrations. Caught three real bugs in one pass that reading
  would not have: an unaliased table reference, a return-type change that `create or replace`
  cannot perform, and a tier ladder that was quietly unfair. Cheap, fast, no Docker Compose,
  no Supabase CLI.
- **Running the economics as a query instead of reasoning about them.** Printing the tier
  ladder across a young board and a mature board side by side exposed a fairness bug that had
  survived a written design review.

## What we would do differently (pitfalls)

| Pitfall | The fix | Guardrail it became |
|---|---|---|
| **Postgres grants `EXECUTE` to `PUBLIC` on every `CREATE FUNCTION`.** `revoke all on <table>` does NOT touch function ACLs, and PostgREST exposes every `public`-schema function at `/rest/v1/rpc/<name>` to the anon key. Every `security definer` function is callable by anyone, bypassing all route-level bot/origin/rate-limit checks. Worst case found: a payment-applying RPC that trusts the caller, combined with a Stripe session id that is handed to the payer in `success_url` — start a huge checkout, abandon it, call the RPC, get free rank. | A final migration that does `alter default privileges ... revoke execute on functions from public`, revokes from existing functions, grants to `service_role` only, then re-grants **only** pure functions and read-only reads that expose nothing beyond the public view. | Every Supabase product ends with a `lock_function_grants` migration, and a `session_user not in ('postgres','service_role')` guard inside each definer function so protection survives a fresh schema paste. Audit query: `proacl IS NULL` means EXECUTE TO PUBLIC. |
| **`create or replace function` cannot change a return type.** Fails mid-migration with "cannot change return type of existing function", which is confusing when it lands halfway through a run. | `drop function if exists <name>(<argtypes>);` immediately before the `create`. | Any migration that redefines a function with new OUT params drops first, with a comment saying why. |
| **A purely relative tier ladder punishes arriving late.** Sizing a building by share-of-leader means someone paying $600 on a mature board gets a market stall, while someone who paid the same $600 early ratcheted to a tower and kept it. Same money, different building, decided by arrival time. | `tier = least(cap, greatest(absolute(spend), relative(share)))`. The relative half keeps a young board varied; the absolute half keeps a mature board fair. | Any spend-to-status ladder needs both halves, and the ladder gets printed across a young board and a mature board before it ships. |
| **A saturating ladder flattens the top.** Once everyone above a threshold shares the top rung, the skyline becomes a wall. | Let the archetype saturate but keep a continuous dimension moving: `height = base + log10(spend / rung_floor)`. | Discrete tiers pick the *shape*; a log term keeps a *magnitude* visible past the top rung. |
| **Email paths that fail silently in three places.** A missing env var returns early with no log; a missing recipient returns early with no log; API failures are `console.warn` inside `Promise.allSettled`. A missing key means zero notifications and zero signal anywhere. | Log loudly when a notification is skipped for a config reason, and record a `notification_skipped` row in the first-party events table so it shows up in admin rather than nowhere. | Best-effort sends must still be observable. "Never breaks the webhook" is correct; "never tells anyone it didn't send" is not. |
| **One Stripe account serving two products cross-talks.** Every webhook endpoint on an account receives *all* of that account's events, so product A's webhook receives product B's `checkout.session.completed`, fails to find the bid, and 500s to force a Stripe retry — forever, until Stripe disables the endpoint. | Tag every Checkout Session with `metadata.product`, have each webhook 200-ack and ignore anything that is not its own, **and** treat "no bid for this session" as a 200 ack rather than a 500. | Sharing a payment processor across products requires a product discriminator in metadata from the very first session. |
| **`localStorage` keys collide between sibling products.** A fork inherits its parent's key prefixes; two products on one domain (or one localhost port) fight over theme and reaction state. | A `storageKeys` block in the single config file, namespaced per product. | Forks rename storage prefixes as part of the fork checklist, not later. |
| **Hardcoding a TLD in a wordmark regex.** `site.name.split(/(?=\.lol$)/)` silently no-ops the moment the domain changes, in every place it was copy-pasted. | Store the wordmark as an explicit `["bids", ".town"]` pair in config. | Never derive branding from a regex over the domain. |
| **A stale `schema.sql` beside a live `migrations/` directory.** The parent product's `schema.sql` was missing three migrations' worth of tables and columns, so anyone building from it got the wrong database. | On a fork, collapse the whole history into one clean init migration and delete the drifted artefact. | `schema.sql` is either generated from migrations or it does not exist. |
| **`h >> k` on a uint32 hash goes negative.** JS `>>` is a signed shift: any hash above 2³¹ becomes negative, a negative modulo yields a negative index, and the array pick silently returns `undefined` — for us, invisible banner patterns and colours on roughly half of all slugs. | Use `>>>` everywhere a hash is shifted for indexing. A unit test asserting "only known patterns and valid hexes" caught it within the hour it was written. | Every hash-indexed pick uses unsigned shifts, and every generator has a test that its outputs stay inside the declared enum/format. |
| **Zeros aren't proof of wiring.** A probe returning empty data was read as "database connected" when the schema was never installed. | Positive-signal checks only: read a marker the install writes, or write-then-read. | Live-checks assert real data, never absence-of-error. Full entry in factory launch-gotchas. |
| **Supabase custom schema = no automatic service_role table grants.** RPCs worked, table reads failed silently behind the demo fallback. | Explicit `grant all on all tables/sequences` + default privileges, shipped as the final migration. | Every custom-schema migration set ends with the service_role table-grant block. |
| **Runbooks die by clipboard.** Copying the error to report it erased the SQL install; the retry ran the error text. | Say "copy nothing in between", state what a correct paste's first line looks like, verify with pbpaste. | Clipboard-dependent steps are single-shot and self-verifying. |

| **A hidden browser tab freezes requestAnimationFrame — and everything that hangs off it.** The desktop-app browser pane reports `visibilityState: "hidden"` when not frontmost, so the R3F frameloop, its animations, AND the CustomEvents they dispatch all silently stop. Screenshots show the frozen last frame, which reads as "the feature is broken" when nothing is wrong. | Verify animation in a browser tab that is actually visible (the operator's own Chrome), or trust the headless tests for time-domain behaviour. A quick `requestAnimationFrame` probe settles it in one call. | Before debugging "animation not running" in an embedded pane, check `document.visibilityState` first. |
| **Extension-world CustomEvents drop their `detail` crossing into the page.** A probe dispatched from an extension's isolated world reaches page listeners with `detail: null`, so a working feature looks broken (and a broken probe looks meaningful). | Inject a `<script>` tag so the dispatch runs in the page world, or use a page-context JS tool. | Event-system probes must run in the page's own world; a null-detail guard in listeners keeps hostile/foreign events harmless anyway. |
| **Ad-surface positions calibrated on a rich demo board become street clutter on a young live one.** Fixed offsets (billboard pitch, corner jumbotrons, kerb boards, arch width) collided with the concert, buildings, the Mayor's rally and each other once the town shrank. | Derive every position from the town's actual radii, drop inventory that doesn't fit yet ("less clutter beats full inventory"), and keep the civic core ad-free. | Anything placed by constant offset gets re-derived from layout maths before a different board size ships. |
| **Two counter-rotating orbiters give you an airshow for free.** Near-miss and collision choreography needs no scripted dashes: same runway takeoff, opposite directions, similar radii — convergence period = pi/omega, so every beat (miss ~8s, crash ~15s) is one constant. Kept PURE (no three.js) it is fully unit-testable: min-distance windows, chute landing, cycle wrap. | Put show-control maths in `src/lib/city/*` like everything else; the component only applies poses to refs. | Decorative choreography is still logic: pure module + headless tests, same as scoring. |
| **An invisible full-height container with `pointer-events-auto` eats every click behind it.** The sights-panel wrapper spanned its whole column even when collapsed, so the day/sound buttons under it were dead — no error, no visual clue. | Containers are `pointer-events-none`; only the visible panels re-enable `auto`. | Every floating-chrome wrapper defaults to pointer-events-none; interactivity is opt-in per visible box. |

| **`camera.up` is process state, not frame state.** A spherical-walk mode set `camera.up` to the surface normal each frame; every later consumer (OrbitControls, lookAt) silently inherited it — the aerial view rendered upside-down AFTER the feature exited cleanly. Nothing crashed; three test suites stayed green. | Restore `camera.up` at every exit edge of the mode (ride transitions, effect cleanup), because whoever owns the camera next will trust it. | Any code that writes a shared camera/global must enumerate its exit paths and restore invariants there; an adversarial-review lens on "what does the NEXT consumer inherit" catches what unit tests cannot. |
| **A feature that borrows the pointer must silence the scene's other pointer consumers.** Pointer-lock walk mode left R3F raycast handlers live: the engage click also selected buildings, opened ad tabs, and double-click started a camera tween that fought the first-person camera (mount order made the LAST-mounted rig win the frame). | One switch: `setEvents({enabled:false})` for the mode's lifetime + the camera rig swallows queued commands while the mode owns the camera. | Modes that take over an input channel disable that channel's other subscribers wholesale — never handler-by-handler. |

| **A runtime-only crash sailed through every static gate.** Passing `window` where a drei prop expected an element compiled (silenced by an `as unknown as` cast), linted, tested and built clean — then threw an uncaught TypeError loop on every mount (`window.style` does not exist) and Chrome killed the tab. | Post-deploy verification in a REAL fresh browser tab reading the console; the fix used the API built for the job (`listenToKeyEvents(window)`). | Every deploy ends with a fresh-tab production console check. A double-cast in a diff is a stop sign: the types were right. |
| **A silent no-op patch was reported as a fix.** `python str.replace` returns the unchanged string on mismatch; the "fixed" file never changed, and the claim shipped. A stale console buffer in the embedded pane then masked which errors were current. | Scripted patches end with asserts on the resulting content; error triage uses a brand-new tab, never a reused console. | Patch tools must fail loudly (Edit tool or assert-after-replace). Console buffers are per-tab historical logs, not live truth. |

## Open questions

- Whether the 12-hour cap on Moon trips should be per-purchase or a rolling ceiling across
  queued trips. Currently enforced at checkout, not in the schema.
- Whether ad-surface allocation should be re-evaluated continuously or snapshotted, so an
  advertiser who paid for the airship does not lose it mid-hour to a competing bid.

## 2026-08-23 — live-traffic session: money, logos, economy, scale

| What bit us | What we did | The rule now |
|---|---|---|
| **A real customer paid and the town never showed it.** Stripe took $1; the webhook called `apply_paid_bid`, the pooler-broken guard rejected it, the route 500'd, Stripe retried into the same wall, and the bid sat `pending` — invisible to everyone. The failure was CORRECT (never fake a payment), but nothing surfaced it. | Built `reconcilePendingBids()`: ask Stripe directly about every pending session and apply what genuinely paid. Wired to an admin button, the daily cron, and a red "N payments in limbo" banner. | Every money path needs three things, not one: the happy path, a **sweep that re-asks the payment provider**, and a **surface that makes stuck money impossible to miss**. A correct refusal that nobody can see is an outage. |
| **One malformed stored favicon painted the whole town with monograms.** The icon scraper's single regex demanded rel-before-href and stopped at the first quote of either kind, so a `data:` SVG icon containing single quotes was stored beheaded. Because every surface derives from one board row, one bad value broke the rail, billboards, blimp, cinema and concert at once. | Attribute-aware extraction; **inline the icon bytes into the row** at claim time so the town owns its logos; **self-heal on read** (a board query that sees a truncated icon re-scrapes and repairs the row, once per slug per process). | Single-source-of-truth cuts both ways: one poisoned row poisons everything downstream, so the repair has to be automatic too. Store the bytes you depend on; never keep a remote host in the hot path. |
| **`side: THREE.DoubleSide` mirrors the back face.** Flags read correctly from the front and as a looking-glass from behind — logo reversed, name backwards. Looks like a texture bug; it is basic geometry. | Two front-facing planes back to back, offset 0.01. | Any plane carrying TEXT or a LOGO gets two front faces, never DoubleSide. |
| **An idle browser tab minted $70,000 of play money overnight.** Browsers *throttle* background `setInterval` — they do not stop it — so a wallet paying $100 per tick kept earning while nobody was there, and every price in the game became meaningless. | Payday now accrues **engaged time only**: tab visible AND in walk mode AND input within 60s. Plus a hard wallet ceiling, applied on load so legacy balances get trimmed. | Any timer that grants value must measure *engaged* time, not wall-clock, and be bounded by a ceiling. "The tab was open" is not "the user was there". |
| **A per-visitor write that also recomputes a town-wide answer.** `touch_presence` ran three `count(*)` aggregates AND a cleanup `DELETE` on **every heartbeat** — at 10k visitors that is ~650 aggregate scans a second, all producing the identical number. | Split into a cheap per-visitor write, a **cacheable** counts read (10s memo per instance), and a swept cleanup on the daily cron. | In a hot path, separate what is **per-caller** from what is **per-town**. The per-town half is cacheable by definition — recomputing it per caller is the whole cost. |
| **PostgREST silently caps result sets at 1000 rows**, so de-duplicating in JS quietly under-counts. Our "unique clickers" figure would have gone *wrong* — not slow — exactly as a listing got popular. | `count(distinct ip_hash)` in a SQL function; fails soft to no count rather than a wrong one. | Never aggregate over an unbounded table in application code. If the answer needs all the rows, it belongs in SQL. |
| **"Live looks worse than staging" was browser zoom.** Chrome stores zoom **per origin**; the live domain had a stale zoom-out, staging had none. Two screenshots, same commit, different layout — and a real risk of "fixing" a non-bug. | Confirmed same commit, told the operator to press Cmd+0. | Before investigating a visual diff between two deploys, verify the *commit* is different. Per-origin browser state (zoom, storage, console buffer) fakes UI bugs convincingly. |
| **A killed multi-agent workflow leaves half-edited files in the tree.** Agents write as they go; when the run is stopped, some files are mid-edit and the "done" report never arrives. | `git status` + revert the partial files, then re-run only the lost agents (the finished ones' work was already on disk and kept). | After any interrupted parallel run, reconcile the working tree with git BEFORE re-running anything. |

## Decisions taken this session (product, not code)

- **The 10%-over-leader bid ceiling is GONE.** Anyone may pay any amount and take any rank in one move; the only cap left is the card processor's per-charge maximum. Rationale: the operator wants big swings and a spending spree; the answer to being outbid is outbidding.
- **Spree pricing**: $1 / $5 / $7 / $10 / $25 / $100 / $600, with the city-cap thresholds set EQUAL to the rung prices, so your own purchase always unlocks your own size instantly. Past the top rung height keeps compounding, so a $10k skyscraper visibly dwarfs a $600 one.
- **Moon time**: 6h maximum per listing (was 12), first 3h flat at $5, then each additional hour doubles ($10/$20/$40). A fair queue: buying while a flag flies puts yours next in line.
- **Rocket rides** (walk mode) double per completed trip, capped at $10,000 — the Moon should feel like an occasion, not a commute.
- **Every open ad surface advertises its RANK**, never a generic "your ad here"; the two landmark skyscrapers are #1's perk (mega-posters, logo above name).
- **Admin destructive actions are two-step and backed up**: removal arms a red confirm bar, and the complete row + full bid history is written to the events ledger *before* deletion (events.listing_id is ON DELETE SET NULL, so the record outlives the row). Anything with a paid bid cannot be removed at all until refunded in Stripe.
